The Grilling Room

Interview Defense Q&A Blueprint

Expected in Google L4 / Meta E4 Systems Loops
warning Question 01 • Safety Invariant

"How do you handle Split-Brain when a partitioned former leader keeps taking writes?"

The Defense: Raft completely eliminates split-brain by requiring a strict majority quorum (N/2 + 1) before committing any entry to the log.

If an old leader is isolated in a minority partition (e.g., 2 nodes out of 5), it will accept client writes conditionally, but its AppendEntries RPCs will never gain quorum approval. It cannot advance its commitIndex.

> Follow-up nuance: Implement Leader Leases or ReadIndex verification to ensure linearizable stale-read prevention during transient partitions.
Interview Frequency: Very High 100% Core
psychology Question 02 • Architectural Tradeoffs

"Why did you choose Go over C++ or Rust for this consensus implementation?"

The Defense: Go provides first-class primitives for CSP concurrency (goroutines, channels, and select), which directly maps to Raft's asynchronous state machine timers and RPC heartbeats.

While Rust provides zero-cost abstractions without GC pauses, Go allowed us to hit 4.8ms p99 write latency by pre-allocating byte slice memory pools (sync.Pool) to avoid GC thrashing while drastically accelerating development velocity.

> Demonstrates pragmatic engineering judgment rather than dogmatic language partisanship.
Interview Frequency: High Design Tradeoff
memory Question 03 • Production Longevity

"How does your log compaction avoid memory exhaustion without blocking incoming writes?"

The Defense: We decoupled snapshot generation using Copy-on-Write (CoW) semantics on the underlying in-memory Skip-List.

When a snapshot threshold is hit (e.g. 50,000 entries), a background worker acquires a brief read-lock to clone the root pointer, then asynchronously serializes the snapshot to an mmap disk buffer without stalling the active leader's gRPC ingest path.

> Mention InstallSnapshot streaming via chunked gRPC streams for nodes that rejoin after extended outages.
Interview Frequency: High Storage Internals
